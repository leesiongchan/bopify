## Handoff ownership fix on 2026-10-11

Safe timestamp diagnostics established the handoff race: the destination accepted a self-owned publication reply at `changed_timestamp_ms=1791703434354`, then consumed a queued peer snapshot at `1791703434338`. That 16 ms older snapshot deactivated the destination, cleared its context resolver, and led to Unavailable at the restoration deadline. Baseline cleanup passed in this diagnostic. Evidence: `/tmp/bopify-handoff-response-before-fix.log`.

The pinned client now remembers the greatest positive server snapshot timestamp accepted from Dealer or a successful parsed self-owned publication reply. It rejects only strictly older positive snapshots before changing ownership or restoration state. Equal and unversioned snapshots remain eligible; newer foreign/empty owners still trigger handoff or connection loss. Foreign publication replies cannot advance the watermark and hide an ownership-loss update. Stale traffic does not extend the absolute restoration deadline. Another maintained client also guards stale activation updates, using player timestamps ([go-librespot, commit 4dbc099, 2026-10-03](https://github.com/devgianlu/go-librespot/blob/4dbc099f46da3529adaa85feb97c4f49deb0b130/daemon/player.go#L261)); this fix instead compares the same server snapshot field on both channels. Positive timestamps are assumed to order server snapshots within this session; the private protocol provides no published monotonicity guarantee.

Separate regressions reproduced failed cleanup leaving a genuine old owner active, and a late request-ID callback re-arming playback after handoff. Local ownership now becomes inactive before network cleanup; actual ownership/transport loss requests a local audio stop and invalidates the old request. Inactive stopped devices ignore late playback callbacks. Terminal loss is emitted before stopping, while ordinary disconnection is delivered even if cleanup fails. Explicit `disconnect(false)` retains its existing audio behavior. The synthetic regression verifies state and callback safety, not audible output. Evidence: `/tmp/bopify-handoff-red.log`, `/tmp/bopify-handoff-failed-cleanup-red.log`, `/tmp/bopify-handoff-late-event-red.log`.
